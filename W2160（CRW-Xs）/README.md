## 1. 硬件与驱动踩坑排查实录

在初期测试过程中，读卡器接在 USB-to-RS232 线连接电脑时，任何软件打开对应端口（`COM6`）均报错：
> `A device attached to the system is not functioning (错误代码 31: 连到系统上的设备没有发挥作用)`

通过严格的底层 Win32 API 追踪与单步隔离测试，查明了技术根因：
1. **山寨 HL-340 芯片与新版驱动冲突**：商家售卖的线材使用了假冒/克隆的 HL-340 黑胶芯片，Windows 11 自动更新的最新官方驱动（`CH341S64.SYS` 2024/2026 版）下发波特率配置指令（`SetCommState` / `IOCTL_SERIAL_SET_BAUD_RATE`）时，克隆芯片无法响应，导致堆栈报错 31。
2. **严密的对照实验**：
   * 拔掉读卡器单插新线依然报错，排除读卡器干扰。
   * 插同一台电脑另一根旧的路由器配置线，所有波特率全部秒通，排除电脑与 USB 接口问题。
   * 将驱动降级至 2011 年宽松版本（`3.3.2011.11`）后，`COM6` 恢复正常打开与收发数据。
3. **详细报告参见**：[driver_issue_evidence.md](driver_issue_evidence.md)。

## 2. 握奇 W2160 底层通信协议规范

W2160 采用标准串口通信（默认 **9600, 8, N, 1**，支持偶校验 **E**），底层采用 **T=1 帧封装 + BCC 校验**：

### 2.1 发送帧结构 (PC -> Reader)

| 字节偏移 | 字段名称 | 长度 | 描述与取值 |
| :--- | :--- | :--- | :--- |
| `0` | **NAD** | 1 Byte | 卡槽标识：<br>• `0x15`：非接触卡 (NFC / Mifare / CPU卡 / YubiKey)<br>• `0x12`：接触式用户卡槽<br>• `0x16 ~ 0x19`：SAM1 ~ SAM4 卡槽<br>• `0x00`：读卡器系统内置指令 |
| `1` | **LEN_H** | 1 Byte | APDU 长度高字节 |
| `2` | **LEN_L** | 1 Byte | APDU 长度低字节 |
| `3 ~ N` | **APDU** | N Bytes | 标准 ISO 7816-4 APDU 指令 (`CLA INS P1 P2 Lc Data...`) |
| `N+1` | **BCC** | 1 Byte | 纵向冗余校验码：从 `NAD` 到 `APDU` 最后一个字节的所有数据做 `XOR`（异或） |

### 2.2 接收帧结构 (Reader -> PC)

| 字节偏移 | 字段名称 | 长度 | 描述与取值 |
| :--- | :--- | :--- | :--- |
| `0` | **NAD** | 1 Byte | 卡槽标识半字节翻转（如发送 `0x15`，接收返回 `0x51`；发送 `0x12`，返回 `0x21`） |
| `1` | **LEN_H** | 1 Byte | 响应数据长度高字节 |
| `2` | **LEN_L** | 1 Byte | 响应数据长度低字节（包含数据及末尾 2 字节 SW） |
| `3 ~ M-1` | **DATA** | 可选 | 卡片返回数据或 ATR 响应串 |
| `M, M+1` | **SW1 SW2** | 2 Bytes | 卡片/读卡器状态码（如 `9000` 表示成功，`6FF0` 表示超时未寻到卡） |
| `M+2` | **BCC** | 1 Byte | 全帧异或校验码 |

* 输入 `nad 15` 或 `nad 12` 切换非接触 / 接触大卡

```powershell
python test_yubikey.py COM6
```

```python
from w2160_reader import W2160Reader

with W2160Reader("COM6") as reader:

        print("读到卡片 ATR:", data.hex())
```

## 5. 硬件方案与芯片架构解密

通过实物拆解确证，**老款 RS-232 串口版本（原 CRW-Xs）** 与 **后续升级的 USB 版本** 采用了两代完全不同的硬件架构：

### 5.1 初代 RS-232 串口版 (物理拆机真实确证：MFRC531 + uPSD3422E)

这是 2003~2007 年代国内金融、交通领域**天花板级别的“上古工业神机”组合**：

```text
                  ┌───────────────────────────────────────────────┐
                  │          STMicroelectronics uPSD3422E         │
                  │  • Turbo 8051 内核 (4T 周期，最高 40MHz)        │
                  │  • 片上集成 CPLD (可编程系统逻辑单元 PSD)        │
                  │  • 双 Flash 架构 (Main Flash + BootROM)       │
                  │  • 硬件 UART0 (接 MAX232 驱动 RS-232 串口)     │
                  └──┬─────────────────────────────────────────┬──┘
                     │ (8 位并口数据/地址复用总线 ALE/RD/WR)    │ (CPLD 译码片选)
                     ▼                                         ▼
          ┌──────────────────────────────────┐      ┌───────────────────────┐
          │      Philips/NXP MFRC531         │      │ 内部 2~4 个 SAM 卡槽  │
          │  • ISO 14443 Type A + B 双协议    │      │ (由片上 CPLD 译码管理) │
          │  • 硬件 Crypto1 (Mifare 加密)    │      └───────────────────────┘
          │  • 8 位并行主机接口 (64B FIFO)   │
          └─────────────────┬────────────────┘
                            ▼
                     大面积非接射频天线
```

1. **射频前端：Philips / NXP MFRC531（黄金标杆）**：
   * **为什么不用低成本的 RC500？** 当年绝大多数低端读卡器只用 RC500（仅支持 Type A / Mifare One，不支持 Type B）。
   * 握奇为了面向社保、二代身份证及高安全金融卡招标，不惜工本采用了 **MFRC531**——全球第一款完整硬件支持 **ISO/IEC 14443 Type A 与 Type B** 的专业射频收发芯片。
   * 这也是为什么你的 YubiKey 5、交通银行金融 CPU 卡在上面能够**秒读且射频场极其稳定**的硬件根本原因！
2. **主控系统：ST uPSD3422E（Turbo 8051 + 片上 CPLD）**：
   * **内核性能**：采用意法半导体（ST）的高性能 4T 周期 Turbo 8051，运算速度是远古 12T 标准 8051 的三倍。
   * **片上集成 CPLD（PSD 单元）**：这是 uPSD 最惊艳的工业设计！MFRC531 采用经典的 8 位并行总线接口（带 ALE 锁存信号）。uPSD3422E **不需要外挂任何 74HC373 锁存器或译码门电路**，直接利用单片机内部集成的 CPLD 可编程逻辑块完成地址重映射，将 MFRC531 和内部 SAM 卡座直接映射到 8051 的 `XDATA` 外部数据空间！
   * **双 Flash 银行与安全隔离**：内置独立的主 Flash 与辅助 Boot Flash，这也是当年握奇实现可靠在线固件升级（IAP）同时避免固件损毁的硬件根基。

---

### 5.2 后续纯 USB 版 / 成本优化升级版 (STM32F103 + TDA8024TT)

到了 2008 年之后，随着 ARM Cortex-M 架构普及，硬件方案演进为现代高度集成的方案：

```text
                  ┌───────────────────────┐
                  │    STM32F103C8T6      │
                  │ (ARM Cortex-M3 72MHz) │
                  └──┬─────────────────┬──┘
                     │ (SPI 总线)      │ (ISO 7816 控制线)
                     ▼                 ▼
          ┌────────────────────┐   ┌───────────────────────┐
          │  13.56 MHz 射频前端 │   │     NXP TDA8024TT     │
          │ (RC522 / FM17520)  │   │ (接触式智能卡接口芯片)  │
          └──────────┬─────────┘   └──────────┬────────────┘
                     ▼                        ▼
               板载非接天线            内部 2~4 个 SAM 卡槽
```
* **主控**：换用 ARM Cortex-M3 内核的 STM32F103，直接利用片上原生 USB 全速控制器直连 PC，不再需要 MAX232 串口芯片。
* **模拟前端**：接触式/SAM卡驱动由片上 CPLD 方案改为专用的 **NXP TDA8024TT** 芯片（提供 1.8V/3V/5V 稳压与 8kV ESD 保护）；射频芯片则由并口总线改用 SPI 挂载的低成本芯片。

## 6. 原厂扩展系统控制指令集 (B0 系列 APDU)

除了针对卡片的标准 ISO 7816-4 APDU 指令之外，握奇为 W2160 / CRW-X 读卡器定义了一套专用的 **`B0` 系列系统级管理控制指令**：

| 功能分类 | 目标卡槽 (NAD) | 指令十六进制 (Hex) | 参数与作用说明 |
| :--- | :--- | :--- | :--- |
| **控制蜂鸣器鸣叫** | `0x00` (Reader) | `B0 F2 P1 P2 00` | `P1`、`P2` 控制蜂鸣器鸣响时长与延时（例如发 `B0 F2 01 00 00` 触发短鸣一声提示刷卡成功） |
| **控制 LED 指示灯** | `0x00` (Reader) | `B0 17 00 23 01 [DATA]` | 通过 Data 字节位掩码控制绿灯、蓝/红灯的状态（常亮/闪烁/熄灭） |
| **射频场关场 (RF Power OFF)** | `0x15` (RF) | `B0 15 0E 00 01 00` | 关闭 13.56 MHz 射频天线供电，强制让在场卡片下电（用于卡片重置或安全登出） |
| **非接卡复位 (仅限 Type A)** | `0x15` (RF) | `B0 12 00 00 01 01` | 激活射频场并仅针对 Type A 卡（M1、CPU卡）寻卡，返回 ATR / UID |
| **非接卡复位 (仅限 Type B)** | `0x15` (RF) | `B0 12 00 00 01 02` | 激活射频场并仅针对 Type B 卡（如二代证）寻卡 |
| **速率协商复位 (PPS)** | `0x15` (RF) | `B0 12 P1 P2 00` | 执行复位并进行 PPS 速率协商（支持 106k ~ 424k 通讯速率设置） |
| **配置非接等待超时** | `0x15` (RF) | `B0 06 00 00 04 [DATA]` | 配置非接卡等待卡片响应的 FWI 时间（单位微秒），防止耗时计算（如 RSA/ECC）超时 |

### 核心状态字 (SW1 SW2) 快速诊断表
* `90 00`：指令执行成功。
* `62 00` / `62 01`：射频场内无卡（No card in RF field）。
* `70 xx` / `75 xx`：非接触卡复位失败（碰撞冲突或防冲突校验未通过）。
* `6F F0`：卡片通信链路超时或未知通信错误。

## 7. 产品代际演进与后续版本同源性分析

### 7.1 后续纯 USB 版本的演进 (直出 USB 线缆)
* **硬件标识**：`USB\VID_163C&PID_0A01`（系统内显示为 `Watchdata CRW-X SmartCard Reader`）。
* **通信协议**：采用标准 **USB-HID 免驱模式**。
* **协议同源性**：STM32 固件中仅仅将原本在串口传输的 `[NAD] [LEN] [APDU] [BCC]` 报文直接打包进 64 字节的 **USB HID Report**（帧头前置 `Report ID = 0x00`，填充至 65 字节送入端点）。**内部的指令集和状态机逻辑 100% 同源**。

### 7.2 现代多功能“四合一”W2160 (带磁条与扫码窗)
* **型号背景**：政务、医保及医院招投标采购中，常由于历史招标文件型号固化，后续升级的台式多合一终端（带磁条刷卡槽、二维码扫码窗、甚至二代证模块）依然沿用 **W2160** 的大名。
* **协议兼容**：四合一新款 W2160 面对非接触卡与接触卡时，完全兼容原厂这套 `NAD` 路由与 `B0 12 ...` 指令集；上层原厂动态库（`wdcrwx.dll` / `Crwicc.dll`）中的 `CT_open("hid1", ...)` 接口在两代设备间保持了无缝向下兼容。

## 8. 跨平台支持备忘 (macOS / Linux)

当前 Python 示例代码基于 Windows 原生 Win32 API (`ctypes.windll.kernel32`) 实现。若需要在 macOS 或 Linux 上运行：
1. **通过 pyserial 统一接口**：只需使用 `serial.Serial(port, 9600, timeout=1.0)` 包装收发即可实现全平台通用。
2. **零依赖原生 POSIX 实现**：在不安装 `pyserial` 的情况下，利用 Python 标准库内置的 `termios`、`tty`、`fcntl` 与 `os.open` 直接配置串口属性（`B9600`, `CS8`, `CLOCAL`, `CREAD`），端口路径通常形如 `/dev/cu.usbserial-*` 或 `/dev/cu.wchusbserial*`。
